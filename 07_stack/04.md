Stack Frame Management in 32-bit Assembly
Step-by-Step Stack Explanation
Step 1: Calling the function
call work


Execution begins at _start. The CALL instruction pushes the return address onto the stack. This address identifies where execution should continue after work finishes.

ESP decreases by 4 bytes because this is a 32-bit program.

Step 2: Saving the base pointer
push ebp
mov ebp, esp


- push ebp saves the previous base pointer onto the stack, decreasing ESP by 4 bytes.
- mov ebp, esp makes EBP point to the current stack position.
EBP now provides a fixed reference point for accessing local variables within the function.

Step 3: Allocating space for local variables
sub esp, 8


ESP decreases by another 8 bytes, reserving space for two 4-byte local variables.

Step 4: Storing local variables
mov dword [ebp - 4], 100
mov dword [ebp - 8], 200


- The value 100 is stored at EBP - 4.
- The value 200 is stored at EBP - 8.
These values are stored directly in the allocated stack space rather than being pushed individually.

Step 5: Retrieving local variables
mov eax, [ebp - 4]
mov ebx, [ebp - 8]
nop


- The value 100 is copied from the stack into EAX.
- The value 200 is copied into EBX.
- NOP performs no operation and does not affect the stack.
The values remain in their stack locations because MOV copies data without removing it.

Step 6: Restoring the stack
mov esp, ebp
pop ebp


- mov esp, ebp restores ESP to its position before local variable allocation. This releases the 8 bytes reserved for local variables.
- pop ebp retrieves the previous base pointer and restores it. ESP increases by 4 bytes.
Step 7: Returning from the function
ret


RET retrieves the return address previously pushed by CALL.

ESP increases by another 4 bytes, and execution returns to _start, immediately after the CALL instruction.

Step 8: Program termination
mov eax, 1
xor ebx, ebx
int 0x80


- EAX is set to 1, selecting the Linux 32-bit exit system call.
- EBX is cleared to zero, indicating successful termination.
- int 0x80 transfers control to the operating system to terminate the program.
No additional stack operations occur during termination.

Observations from Execution
When running the program using GDB, the following observations can be made:
1. CALL decreases ESP by 4 bytes to store the return address.
2. PUSH EBP decreases ESP by another 4 bytes to save the previous base pointer.
3. EBP is established as the reference point for the function's stack frame.
4. SUB ESP, 8 reserves 8 bytes for local variables.
5. The values 100 and 200 are stored at EBP - 4 and EBP - 8 respectively.
6. MOV copies these values into EAX and EBX without removing them from the stack.
7. MOV ESP, EBP releases the allocated local variable space.
8. POP EBP restores the previous base pointer.
9. RET retrieves the return address and transfers execution back to _start.

Conclusion
This program demonstrates how a 32-bit stack manages function calls and local variables. When work is called, the return address is pushed onto the stack. The function then saves the previous base pointer and establishes a new stack frame using EBP.

Eight bytes are allocated for local variables, where 100 and 200 are stored. These values are copied into EAX and EBX without being removed from the stack.

Before returning, the function restores ESP and EBP to their previous states. RET then retrieves the saved return address and resumes execution in _start.

Key observation: The main difference between this program and the previous 64-bit stack frame example is the size of the stack operations. In 32-bit mode, PUSH, POP, CALL and RET use 4-byte stack entries instead of 8-byte entries.
