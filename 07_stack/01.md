PUSH and POP Stack Operations
Step-by-Step Stack Explanation
Step 1: Loading values
mov rax, 100
mov rbx, 200

The values 100 and 200 are loaded into RAX and RBX respectively. 
These instructions do not affect the stack, so RSP remains unchanged.

Step 2: Pushing values onto the stack
push rax
push rbx

- push rax places 100 onto the stack and decreases RSP by 8 bytes.
- push rbx places 200 onto the stack and decreases RSP by another 8 bytes.
The stack follows the Last In, First Out (LIFO) principle. Therefore, 200 is now at the top of the stack, followed by 100.

Step 3: NOP instruction
nop

NOP (No Operation) does not modify registers or affect the stack. RSP remains unchanged.

Step 4: Popping values from the stack
pop rcx
pop rdx

- pop rcx removes 200 from the top of the stack and stores it in RCX. RSP increases by 8 bytes.
- pop rdx removes 100 and stores it in RDX. RSP increases by another 8 bytes.
After both POP instructions, RSP returns to its original position.

Step 5: Program termination
mov rax, 60
xor rdi, rdi
syscall

RAX is set to 60, which represents the Linux exit system call. 
RDI is cleared to zero to indicate successful termination. 
The syscall instruction terminates the program.

Observations from Execution
When running the program using GDB, the following observations can be made:
1. RSP decreases by 8 bytes every time a value is pushed onto the stack.
2. After both PUSH instructions, the value 200 is at the top of the stack.
3. The first POP retrieves 200 into RCX.
4. The second POP retrieves 100 into RDX.
5. RSP returns to its original position after both values are popped.
6. The final register values are RAX = 60, RBX = 200, RCX = 200 and RDX = 100.

Conclusion
The program demonstrates how the stack uses the LIFO principle to store and retrieve values. The two PUSH instructions decrease RSP by a total of 16 bytes, while the two POP instructions increase it by the same amount.

The values are retrieved in reverse order: 200 is placed in RCX, followed by 100 in RDX. Once both values are removed, RSP returns to its original position, showing that the stack space used by the program has been released.
