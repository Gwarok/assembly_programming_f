Stack Operations Using CALL and RET
Step-by-Step Stack Explanation
Step 1: Loading the initial value
mov rax, 10


Execution begins at _start. The value 10 is loaded into RAX. No stack operation occurs, so RSP remains unchanged.

Step 2: Calling the function
call calculate


The CALL instruction pushes the return address onto the stack. This address points to the instruction immediately following the CALL, which is after_call.

Since this is a 64-bit program, the return address occupies 8 bytes. RSP decreases by 8 bytes.

Step 3: Executing the function
calculate:
    add rax, 5


The function adds 5 to the existing value in RAX.

RAX changes from 10 to 15.

No values are pushed onto or popped from the stack during this instruction. RSP remains unchanged.

Step 4: Returning from the function
ret


The RET instruction retrieves the return address stored on the stack by CALL.
- The return address is removed from the stack.
- RSP increases by 8 bytes.
- Execution resumes at after_call.
RAX retains its value of 15 because RET does not modify it.

Step 5: Continuing execution
after_call:
    nop


Execution continues after the function returns. NOP performs no operation and does not affect the stack.

At this point, RAX contains 15 and RSP has returned to its original position.

Step 6: Program termination
mov rax, 60
xor rdi, rdi
syscall


RAX is set to 60 to select the Linux exit system call. RDI is cleared to zero to indicate successful termination. The syscall ends the program.

No additional stack operations occur.

Observations from Execution
When running the program using GDB, the following observations can be made:
1. Initially, RAX contains 10 and RSP points to its starting position.
2. When CALL executes, RSP decreases by 8 bytes because the return address is pushed onto the stack.
3. Inside calculate, RAX changes from 10 to 15.
4. The ADD instruction does not affect RSP.
5. When RET executes, the return address is retrieved and RSP increases by 8 bytes.
6. Execution resumes at after_call, with RAX still containing 15.
7. The stack pointer returns to its original position before the program terminates.

Conclusion
This program demonstrates how CALL and RET use the stack to manage function execution. When calculate is called, the return address is pushed onto the stack, decreasing RSP by 8 bytes.

The function adds 5 to RAX, changing its value from 10 to 15. Since the ADD instruction does not involve the stack, RSP remains unchanged.

When RET executes, the saved return address is retrieved, increasing RSP by 8 bytes and returning execution to the main program.

Key observation: This program demonstrates that the stack can be used even without explicitly writing PUSH and POP instructions. CALL automatically pushes a return address, while RET automatically retrieves it.
