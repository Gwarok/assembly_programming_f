Program 6: Pushing and Popping 32-bit Values
Step-by-Step Stack Explanation
Step 1: Loading values
mov eax, 0x11223344
mov ebx, 0x1234

Execution begins at _start.
- EAX receives 0x11223344.
- EBX receives 0x1234.
These instructions do not affect the stack, so ESP remains unchanged.

Step 2: Pushing values onto the stack
push eax
push ebx

- push eax stores 0x11223344 on the stack and decreases ESP by 4 bytes.
- push ebx stores 0x1234 and decreases ESP by another 4 bytes.
The last value pushed, 0x1234, becomes the top of the stack.

Step 3: NOP instruction
nop


NOP performs no operation. It does not modify registers or affect the stack. ESP remains unchanged.

Step 4: Popping values from the stack
pop ebx
pop eax

- pop ebx retrieves 0x1234 and places it into EBX. ESP increases by 4 bytes.
- pop eax retrieves 0x11223344 and places it into EAX. ESP increases by another 4 bytes.
Both values return to their original registers, and ESP returns to its initial position.

Step 5: Program termination
mov eax, 1
xor ebx, ebx
int 0x80

- EAX is set to 1, selecting the Linux 32-bit exit system call.
- EBX is cleared to zero, indicating successful termination.
- int 0x80 transfers control to the operating system to terminate the program.
No additional stack operations occur during termination.

Observations from Execution
When running the program using GDB, the following observations can be made:
1. Initially, EAX contains 0x11223344 and EBX contains 0x1234.
2. Each PUSH instruction decreases ESP by 4 bytes.
3. After both PUSH instructions, 0x1234 is at the top of the stack.
4. The first POP retrieves 0x1234 into EBX.
5. The second POP retrieves 0x11223344 into EAX.
6. ESP returns to its original position after both values are popped.
7. Both registers recover their original values before the exit instructions execute.

Conclusion
This program demonstrates how a 32-bit stack stores and retrieves values using PUSH and POP. Each operation involving a 32-bit register uses 4 bytes of stack space.

The values are retrieved in reverse order because the stack follows the Last In, First Out (LIFO) principle. After both POP instructions, ESP returns to its original position.

Key observation: Unlike the previous 64-bit program, which used 8 bytes per PUSH and POP, this program uses 4 bytes per operation. The difference is determined by the processor's operating mode and operand size.
